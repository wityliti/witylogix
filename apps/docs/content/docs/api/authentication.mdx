# Authentication

The Witylogix API uses JWT bearer tokens. Tokens are issued per shop — every login request must include the `shopDomain` to identify which shop the user belongs to.

## Base path

```
/api/v4/auth
```

Auth endpoints are public — no `Authorization` header is required to call them.

---

## Dashboard user login

```
POST /api/v4/auth/login
```

Authenticates a dashboard user (admin, dispatcher, etc.) using email and password.

### Request body

```json
{
  "email": "user@example.com",
  "password": "your_password",
  "shopDomain": "my-store.myshopify.com"
}
```

| Field | Required | Description |
|-------|----------|-------------|
| `email` | yes | User's email address |
| `password` | yes | Minimum 8 characters |
| `shopDomain` | yes | Shopify domain identifying the shop |

### Response

```json
{
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiIs...",
    "refreshToken": "a9f3e2b1c4d5...",
    "expiresIn": "1h",
    "user": {
      "id": "usr_01hx...",
      "name": "Jane Smith",
      "email": "user@example.com",
      "role": "ADMIN"
    },
    "shop": {
      "id": "shop_01hx...",
      "name": "My Store",
      "domain": "my-store.myshopify.com"
    },
    "orgId": "org_01hx...",
    "orgRole": "OWNER"
  }
}
```

`orgId` and `orgRole` are only present when the shop belongs to an organisation.

## Driver login

```
POST /api/v4/auth/driver/login
```

Authenticates a driver using phone number and password. Returns a 7-day access token (drivers use mobile devices with infrequent re-authentication).

### Request body

```json
{
  "phone": "+1 555-0010",
  "password": "driver_password",
  "shopDomain": "my-store.myshopify.com"
}
```

### Response

```json
{
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiIs...",
    "refreshToken": "b7c3d9e2f1a4...",
    "expiresIn": "7d",
    "driver": {
      "id": "drv_01hx...",
      "name": "Carlos Martinez",
      "phone": "+1 555-0010"
    }
  }
}
```

## Refresh token

```
POST /api/v4/auth/refresh
```

Exchanges a valid refresh token for a new access token. The old refresh token is immediately invalidated (**rotation**) and a new one is returned.

### Request body

```json
{
  "refreshToken": "a9f3e2b1c4d5..."
}
```

### Response

```json
{
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiIs...",
    "refreshToken": "x2y7z3w1v4u5...",
    "expiresIn": "1h"
  }
}
```

<Callout type="warn">
Always store and use the latest refresh token returned. Previous tokens are invalidated on rotation. Attempting to reuse an old refresh token returns `401 Unauthorized`.
</Callout>

---

## Logout

```
POST /api/v4/auth/logout
```

Revokes the refresh token session. The access token remains valid until it naturally expires. This call always returns `200 OK` for idempotency (safe to call even if already logged out).

### Request body

```json
{
  "refreshToken": "a9f3e2b1c4d5..."
}
```

### Response

```json
{
  "data": {
    "message": "Logged out"
  }
}
```

## Get current user

```
GET /api/v4/auth/me
```

**Requires authentication.** Returns the profile of the currently authenticated user or driver.

### Response — user

```json
{
  "data": {
    "id": "usr_01hx...",
    "name": "Jane Smith",
    "email": "user@example.com",
    "role": "ADMIN",
    "type": "user",
    "shopId": "shop_01hx...",
    "orgId": "org_01hx...",
    "orgRole": "OWNER"
  }
}
```

### Response — driver

```json
{
  "data": {
    "id": "drv_01hx...",
    "name": "Carlos Martinez",
    "phone": "+1 555-0010",
    "role": "DRIVER",
    "type": "driver",
    "shopId": "shop_01hx..."
  }
}
```

## Forgot password

```
POST /api/v4/auth/forgot-password
```

Initiates the password reset flow by sending a reset link to the user's email. Always returns `200 OK` — never reveals whether the email exists in the system.

Reset links expire after **1 hour**.

### Request body

```json
{
  "email": "user@example.com",
  "shopDomain": "my-store.myshopify.com"
}
```

### Response

```json
{
  "data": {
    "message": "If the email exists, a reset link has been sent"
  }
}
```

---

## Reset password

```
POST /api/v4/auth/reset-password
```

Completes the password reset using the token from the reset email. The token is single-use and expires after 1 hour.

### Request body

```json
{
  "token": "abc123def456...",
  "password": "new_secure_password"
}
```

Password minimum length: 8 characters.

### Response

```json
{
  "data": {
    "message": "Password reset successfully"
  }
}
```

## Using the access token

Include the access token in the `Authorization` header as a Bearer token:

```bash
curl -X GET http://localhost:8000/api/v4/orders \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs..."
```

---

## Token expiry reference

| Token type | Expires in |
|------------|------------|
| User access token | Configured via `JWT_EXPIRES_IN` env var (default `1h`) |
| Driver access token | 7 days |
| User refresh token | 30 days |
| Driver refresh token | 90 days |
| Password reset token | 1 hour |

---

## Roles

The `role` field in the JWT payload controls resource access:

| Role | Description |
|------|-------------|
| `SUPER_ADMIN` | Full access across all resources |
| `ADMIN` | Full access within their shop |
| `DISPATCHER` | Create/update orders, assign drivers |
| `DRIVER` | Update own status, location, and order status |

## Error responses

### Invalid credentials

`401 Unauthorized`

```json
{
  "error": "Invalid credentials"
}
```

### Expired or invalid refresh token

`401 Unauthorized`

```json
{
  "error": "Invalid or expired refresh token"
}
```

### Expired or invalid reset token

`422 Unprocessable Entity`

```json
{
  "error": "Invalid or expired reset token"
}
```

---

## Best practices

1. **Never store tokens in `localStorage`** for production apps — use `httpOnly` cookies or secure storage
2. **Implement refresh logic** — detect `401` responses and refresh the access token before retrying
3. **Logout on uninstall** — call `POST /auth/logout` when the user ends their session to revoke the refresh token
4. **Use HTTPS** — always in production; tokens in transit must be encrypted
